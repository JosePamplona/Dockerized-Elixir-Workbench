# security_review

You have to be able to say, point by point, how your application answers the OWASP Top 10.

**Before:** the question comes from a client or an audit, and the answer is put together by hand and from memory each time; what a scanner could have found is found by a person, or not at all.

**After:** a review in the repository with one section per risk of the current Top 10 — what applies, where the code answers it, what is still open — and one task that runs the checks a machine can run and brings their findings to it.

**Not for:** a penetration test or a certification — it organises what you know about your own code; it does not attack it.
