# versioning

You are about to change something, and there is nowhere to say what changed.

**Before:** the version is `0.1.0` because the generator had to write something, and the history of the project is its git log — which records every commit and answers no question a reader has.

**After:** a version the project chose, and a `CHANGELOG.md` opened at it: an `Unreleased` section to write into as you go, and a template line to uncomment when you cut the release.

**Not for:** bumping the version for you — deciding when `0.1.0` becomes `0.2.0` is the one part of this that cannot be automated.
