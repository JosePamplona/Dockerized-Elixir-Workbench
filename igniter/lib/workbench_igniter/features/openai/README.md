# Cartridge: openai

OpenAI assistant with the Conversations context (per-user persisted
conversations and messages).

* **Task**: `mix workbench.install.openai`
* **Inserted by**: `wb.sh add openai`. It needs an OpenAI account.
* **Requires**: `auth0` (conversations belong to users); the installer
  refuses until it is in.
* **Options**: `--project-name` `--interface`

## Description

Gives the application an AI-powered conversational assistant: users can
open conversations, send messages and get replies generated by OpenAI's
chat models, as a feature of the product itself rather than an external
chatbot bolted on.

The key design decision is persistence with ownership. Every conversation
and every message is stored in the project's own database, tied to the
user it belongs to — so conversations can be resumed later with their
context intact, listed, or deleted, and each user only ever sees their
own. When a conversation continues, its history is sent along to OpenAI,
which is what makes the replies coherent across turns instead of starting
from zero each time. This ownership model is why the feature requires
auth0.

Operationally, the integration stays configurable without touching code:
the API address, key and model are read from environment variables, so
switching models or rotating credentials is a deployment concern, not a
code change. The REST interface exposes the full lifecycle — list, read,
create, continue and delete conversations — documented in the project's
Swagger page like the rest of the API.

## What it installs

* `MyApp.Assistant` (context), `Conversation` and `Message` schemas with
  their two migrations in order (messages references conversations —
  consecutive timestamps via `WorkbenchIgniter.migration_timestamps/2`).
* Chat completion calls go through the app's Finch pool: ensures the
  `{:finch, "~> 0.18"}` dep and the `{Finch, name: MyApp.Finch}` child
  (`--no-mailer` projects lack them).
* Config: the `AI_ASSISTANT_*` environment block in `config/runtime.exs`,
  inserted before the `:prod` block.
* With `--interface rest`: the conversation controller, JSON view, OpenAPI
  schemas and the five `/conversation` routes in `/api/v1`
  (list/get/create/continue/delete).
* Unit tests and `AssistantFixtures`.

**Idempotency**: if `MyApp.Assistant` already exists, notice and no-op.
