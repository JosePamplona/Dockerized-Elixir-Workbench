# test_data — six proposals

Written from the cartridge's NEED.md first, then its README and
DESIGN.md, and nothing else. The era block of the winner goes into
`cover.prompt.txt` verbatim; what follows is the hero paragraph each
era would put in it.

## The need

*Your tests need records, and only one value of each is what the test
is about.* Before: every test builds its user and its order by hand,
and the value that matters is lost among the ones that do not. After:
`insert(:user, name: "Ana")` — valid defaults written once, the one
value in the test, Faker for the rest; on Ash, `generate(user())`
through the action. Not for: replacing a collaborator the code calls,
or the data a production database starts with.

## The register

**Supporting** — the mechanism supplies everyone the scene needs,
plausible and forgettable, so that the one you came for stands alone
where you can see it. Subtitles cast (`THE REST ARE EXTRAS`). Added for
this cartridge. Its neighbours are not it: *custodial* keeps what you
hand it and gives it back, where this one invents what you never
handed it; *hospitable* lays everything out for whoever arrives, and
here the laying-out is the background, not the welcome; *lucid* shows
what you were handling blind, where this one hides the irrelevant on
purpose so that one thing is plain.

Title `TEST DATA`. Subtitle `THE REST ARE EXTRAS` — the design's
thesis: defaults minimal and valid, every value an assertion depends on
written in the test, Faker for what nobody asserts. Badge `4 RULES` —
the four rules the factory module carries in its documentation — as
plain lettering in the era's own type. No furniture unless the era's
own column has one.

The picture's subject is **a crowd and the one**: many figures made
from one pattern, each a little different and none of them the point,
and one of them singled out in plain view. Three things every hero
keeps, because they are what the need says:

* **The many are alike and not identical.** One pattern, varied in
  small things — a hat, a height, a coat — the way Faker varies a name.
  They are ordinary and complete: nobody in the crowd is broken,
  missing, or a blank silhouette with no features, because a default is
  valid.
* **The one is marked in the open**, by a name or a light or a colour
  the viewer can see at once, in the same picture as the crowd — never
  hidden behind, never off in another room: the value the test is
  about is written in the test.
* **The name is `ANA`**, at foreground size, where a hero letters it:
  the README's own override.

No hero draws code, a terminal, a database, a conveyor, a machine
stamping copies or a factory floor: the mechanism is not the subject,
the cast is. Lettering only where a slot below asks for it, at
foreground size.

## The recommendation

**3 · Editorial cover.**

The reason is the box, not the look. A factory *is* a paper doll
chain: one pattern folded once and cut once, every figure valid and
standing, and the test that uses it takes a pencil to exactly one of
them. The editorial entry is the only era whose method is a single
object given room, so it can draw the crowd and the one *as the same
object* — the extras are not a background painted behind the lead,
they are cut from the same strip and holding her hands. The other five
need a stage, a light and an audience to single the one out, and a
spotlight tells a different story: that the one is special in herself.
She is not. She is an ordinary copy somebody wrote a name on, which is
what `insert(:user, name: "Ana")` does, and the pencil marks on the
other six are the Faker in it.

The shelf, as the cover record stands: **big box PC** three times
(exdoc, ash, changelog), **console** three times (exdebug, db_admin,
credo), **home computer** once (version_manager), **manual** five
times (clustering, health_probe, dashboard_extras, precommit,
test_doubles), the seven base cartridges on one shared manual front,
and **editorial** and **early carton** never. Editorial would be the
first.
