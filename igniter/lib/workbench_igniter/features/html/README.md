# html

Phoenix's html for a project generated with `--no-html`, and LiveView on
top of it unless `--no-live`.

HTML is the browser half of a Phoenix project: the `:browser` pipeline
of the router, controllers that "gather the data and perform the tasks
needed for rendering", views named after them (`PageController` /
`PageHTML`) with `embed_templates`, the root layout and `Layouts.app`,
and `core_components.ex` — "a great example of defining function
components to be reused throughout our application", imported by
`use MyAppWeb, :html` ([request life-cycle](https://hexdocs.pm/phoenix/request_lifecycle.html),
[components](https://hexdocs.pm/phoenix/components.html)). It brings
`phoenix_html` and `phoenix_live_view` with it, and `mix help phx.new`
warns that without it "the files generated by `phx.gen.html` will no
longer work".

LiveView is `phx.new`'s `--no-live`: "included by default in Phoenix
applications" ([installation](https://hexdocs.pm/phoenix_live_view/welcome.html)),
and the one flag that removes no dependency — `mix help phx.new` says it
will "comment out LiveView socket setup in your Endpoint and
assets/js/app.js" and drop LiveView's own configuration and the `JS`
commands of the core components. In the generator it is `live = html &&
live`, a condition inside html's templates with no file of its own, so
here it is html's option and not a box: on by default as in `phx.new`,
left out with `--no-live`, and added to a project that has html
without it by running html again (`rerun: :adds`).

Base cartridge. Install it on demand with

```sh
./wb.sh add html             # html, with LiveView
./wb.sh add html --no-live   # html alone
./wb.sh add html             # on a project born --no-live: adds LiveView
mix workbench.install.html [--no-live]
```

## What it installs

Whatever `phx.new` generates for it at the installer's version in the
toolchain — asked of `phx.new` itself (`WorkbenchIgniter.PhxDelta`, see
[mailer](../mailer/) for the mechanism). With Phoenix 1.8.12: `phoenix_html`, `phoenix_live_view` and
`lazy_html` in `mix.exs` with the `:phoenix_live_view` compiler, the
`:browser` pipeline and the `/` route in the router, `html`, `live_view`
and `live_component` in `lib/my_app_web.ex`, the layouts and the core
components, `PageController` with `PageHTML` and the home page,
`ErrorHTML`, `priv/static/images/logo.svg`, the tests of the page and
the error view, the `.heex` formatter plugin, the dev-only static and
gettext live-reload patterns, and the endpoint's live-reload socket
and plug. The html delta is taken with live off, as `phx.new`'s `live`
is `html && live`; then, unless `--no-live`, the live delta on top:
`config :phoenix_live_view` (the root tag attribute, for colocated
CSS), the `LiveSocket` lines of `assets/js/app.js` (with `--no-live`
phx.new writes them commented out), `alias Phoenix.LiveView.JS` and the
JS commands (`show`/`hide`) of the core components, `phx-click` on the
layouts' theme toggle, and the LiveView section of `AGENTS.md`. The
`phoenix_live_view` dependency is html's either way, and the endpoint's
`/live` socket is on with the dashboard too: what only live brings is
its configuration, and that is the option's mark (`state/1` reads it
back as `live`).

The LiveView client needs [esbuild](../esbuild/): the `LiveSocket`
lives in `assets/js/app.js`, which exists only with a bundler, and
`phx.new`'s static placeholder for a project without one is a comment.
On such a project LiveView is configured and served and nothing in the
browser connects to it until esbuild is in — the same as `phx.new
--no-esbuild` with live; the insert says so in a notice.

On a project without [esbuild](../esbuild/) and [tailwind](../tailwind/)
the page gets what `phx.new --no-assets` gives: the markup with its
Tailwind classes, a static `priv/static/assets/default.css` (80 kB)
styling it, and a placeholder `priv/static/assets/js/app.js` that is a
comment — no bundle, no LiveView client. The two builders inserted
afterwards bring their pipelines and take those placeholders away.

Files the project already changed are merged three ways; a conflict is
reported with `phx.new`'s version of the file beside it. The router is
not merged as text: its routes, scopes and pipelines go in as
operations, beside the project's own — an API's `scope "/api"`
stays, active, next to the page's `scope "/"`.

## Options

* `--live` / `--no-live` - LiveView on top of html. Default: on, as in
  `phx.new`. A cartridge that needs LiveView says so as `{"html", live:
  true}` in its `requires` (ash's `--auth password`, `--with ash_admin`),
  and the refusal's remedy is `./wb.sh add html --live`.

## Idempotency

The mark is the `phoenix_html` dependency — a default project carries
it. Re-running adds LiveView when asked and not there (`rerun: :adds`)
and otherwise touches nothing, with a notice; `--no-live` never takes
LiveView out.
